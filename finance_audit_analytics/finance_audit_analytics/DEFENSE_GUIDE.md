# Защита проекта Finance & Audit Analytics

## Какую задачу решает приложение

Когда доходы, расходы и лимиты хранятся в разных таблицах, легко пропустить повторный платёж, потерять чек или поздно заметить перерасход. Приложение собирает операции в одном журнале. По этому журналу оно строит графики, рассчитывает показатели и показывает операции, которые нужно проверить вручную.

Короткое вступление для защиты.

> Мой проект помогает вести учёт доходов и расходов, контролировать бюджет и находить операции, которые требуют проверки. Я покажу, как одна и та же запись влияет на финансовые показатели, отчёт по бюджету и результаты аудита.

## Почему я выбрал эти технологии

- **Python** подходит для проверки данных и расчётов. Для сумм я использую `Decimal`, чтобы, например, сложение 100,10 и 200,20 давало ровно 300,30.
- **Streamlit** позволяет сделать формы, таблицы и навигацию на Python. Интерфейс открывается в браузере, а сервер запускается на компьютере.
- **Pandas** помогает подготовить данные для таблиц и графиков. **Plotly** даёт интерактивные графики. Например, можно навести курсор на месяц и увидеть его показатели.
- **JSON** подходит для локальной работы одного пользователя. Файл можно открыть и скопировать для резервной копии. Для такого проекта не требуется отдельно настраивать сервер базы данных.
- **CSV** нужен для обмена операциями и выгрузки отчётов. **pytest** проверяет расчёты, хранение и работу страниц.

## Как хранятся данные

Операции находятся в файле `data/transactions.json`. У каждой записи есть уникальный ID, дата, тип операции, категория, сумма, описание, способ оплаты, контрагент, сведения о чеке и время создания. Сумма хранится текстом, например `"12000.50"`, и читается как `Decimal`. При редактировании ID и время создания сохраняются.

Лимиты хранятся в `budgets.json`, настройки в `settings.json`, статусы и заметки по аудиту в `audit_reviews.json`. При сохранении приложение проверяет данные, записывает временный файл рядом с основным и заменяет основной файл. Если файл повреждён, приложение показывает предупреждение и блокирует сохранение в этот файл до исправления.

## Как работает аудит

Программа проверяет все сохранённые операции. Фильтры помогают выбрать нужный период, а для расчёта правил остаётся доступна история.

| Правило | Пример проверки |
| --- | --- |
| Крупная операция | Сумма выше установленного порога. При сумме от двойного порога уровень становится критическим. |
| Повторная операция | Совпадают тип, дата, сумма, контрагент и описание. Регистр букв и лишние пробелы не влияют на сравнение. |
| Нет чека | Расход достиг установленного минимума, а подтверждения чека и номера чека нет. |
| Превышение бюджета | Сумма расходов по категории за месяц больше сохранённого лимита. |
| Необычный расход | Расход заметно больше среднего по прошлым расходам в той же категории. Для правила нужна достаточная история. |
| Возможное дробление | Несколько близких по дате расходов одному контрагенту в одной категории. Каждый ниже порога, а вместе они достигают его. |
| Необычная частота | За короткое время у одного контрагента прошло гораздо больше расходов, чем обычно по его истории. |

У результата есть ID, уровень риска, объяснение, рекомендуемое действие и список связанных операций. Пользователь может поставить статус **Open**, **Under Review**, **Resolved** или **False Positive** и сохранить заметку. Результат правила показывает, что нужно проверить документы и обстоятельства операции.

### Откуда берётся балл риска

Вес зависит от уровня: 10 для низкого, 25 для среднего, 55 для высокого и 100 для критического. Для каждой операции берётся самый высокий вес среди открытых результатов и результатов на проверке. Если у операции нет такого результата, её вес равен нулю.

Балл равен 60% от максимального веса плюс 40% от среднего веса всех операций в выборке. Например, при весах 55, 10 и 0 получится 42 после округления. Поэтому балл учитывает и самый серьёзный сигнал, и то, сколько операций затронуто.

### Какие алгоритмы использованы

- Группировка по календарному месяцу и категории для сравнения фактических расходов с бюджетом.
- Группировка по одинаковым реквизитам для поиска дублей.
- Среднее по прошлым расходам для оценки необычной суммы. Если записей не меньше пяти, из выборки исключаются одна самая большая и одна самая маленькая сумма.
- Скользящее окно по датам для поиска возможного дробления и всплесков частоты.
- Взвешенное скользящее среднее для прогноза. Три последних завершённых месяца получают веса 1, 2 и 3. Прогноз равен сумме произведений расходов на веса, делённой на 6. При недостатке данных программа выводит предупреждение.

## Десять возможных вопросов преподавателя

1. **Почему выбрали Streamlit?**  
   Он позволяет написать формы, таблицы и графики на Python. Это удобно для проекта, где основная работа связана с данными.

2. **Почему JSON подходит для проекта?**  
   Журнал небольшой и используется локально одним человеком. JSON легко просмотреть, перенести и скопировать.

3. **Как сохраняются данные после перезапуска?**  
   После каждого успешного сохранения данные записываются на диск. При запуске приложение читает те же файлы из папки данных.

4. **Почему суммы хранятся строками?**  
   Так при чтении можно точно восстановить десятичное число. Для денежных расчётов используется `Decimal`.

5. **Чем одинаковый ID отличается от похожего платежа?**  
   Повторный ID нарушает уникальность записи, поэтому импорт его отклоняет. Два платежа с разными ID могут совпасть по реквизитам. Тогда аудит предложит проверить их вручную.

6. **Что происходит при ошибке в CSV?**  
   Программа проверяет всю партию до записи. При ошибке она показывает номера строк и отклоняет партию целиком.

7. **Можно ли считать высокий балл доказательством мошенничества?**  
   Балл показывает результаты настроенных проверок. Для вывода нужно проверить договоры, счета, чеки и историю платежей.

8. **Как снизили количество случайных срабатываний?**  
   Для необычной суммы и частоты нужна история. Для возможного дробления должны совпасть контрагент и категория, а общая сумма должна достичь порога.

9. **Почему прогноз может ошибиться?**  
   Он основан на трёх месяцах. Разовая покупка, сезонность или неполный журнал могут заметно изменить оценку.

10. **Как вы проверили проект?**  
    Тесты проверяют расчёты, пороги бюджета, правила аудита, импорт, сохранение и пустой журнал. Отдельные тесты открывают все страницы и проверяют сохранение данных через формы.
